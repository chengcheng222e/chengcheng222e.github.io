写作发布指南

这份笔记在库根目录，不在 source/ 下，不会被 Hexo 发布成文章，只作为本地备忘。

五条命令

在 Obsidian 里按 Cmd+P 打开命令面板，输入 博客 即可看到全部命令。

命令 快捷键 作用
博客: 新建文章 Cmd+Shift+N 弹窗填标题/分类/标签 → 自动建 source/_posts/年/月/ 目录、写好 front-matter → 直接打开新文章
博客: 发布当前文章（归档+构建+上线） Cmd+Shift+D 归档草稿 → 提交推送源码 → 全量构建 → 部署到 GitHub Pages（有二次确认）
博客: 启动本地预览 Cmd+Shift+L 后台启动 hexo server 并自动打开浏览器
博客: 停止本地预览 — 关掉预览服务，顺带回收孤儿进程
博客: 重新构建并上线全站 — 不针对单篇，重建整站并部署（改主题、改配置后用）

日常写作流程

  1. Cmd+Shift+N 新建文章，填标题即可，分类标签默认都是 AI
  2. 正常写。截图直接粘贴，PicGo 会自动上传图床并回填链接
  3. Cmd+Shift+L 本地预览，确认排版没问题
  4. Cmd+Shift+D 发布上线

改排版、调样式时用第 3 步预览就够了，不用每次都发布——全量构建要 2.5 分钟左右。

草稿放哪都行

Cmd+Shift+D 会自动判断：

  • 文章已在 source/_posts/ 下 → 跳过归档，直接发布
  • 文章在库里其它位置（比如根目录当草稿写） → 按 front-matter 里的 date 自动移动到 source/_posts/年/月/，再发布

所以你可以先在根目录随手写草稿，写完一键发布时它自己会归位。

脚本文件在哪

四个脚本在 scripts/ 目录下。Obsidian 不显示 .sh 文件，要看内容请用外部编辑器或终端打开：

文件 作用
scripts/new-post.sh 建目录 + 写 front-matter + 用 obsidian:// 协议打开新文章
scripts/publish.sh 归档 → git 提交推送 → 构建 → 部署，支持 --no-deploy 只构建不上线
scripts/preview.sh 后台预览服务，stop 参数用于停止
scripts/_common.sh 公共库：探测 node 路径、封装 hexo 调用、文件名净化

命令去哪改

  • 改快捷键：设置 → 快捷键 → 搜 博客
  • 改弹窗默认值（比如默认分类不想是 AI）：设置 → Shell commands → 找到「新建文章」→ 编辑对应 Prompt 字段的默认值
  • 看命令原文：设置 → Shell commands，列表里能看到每条命令实际执行的脚本路径与参数

几个注意事项

  • obsidian-git 每分钟自动提交一次（文件一变就备份）。在这个库里做临时操作时留意，临时文件会被自动 commit。
  • 文章 front-matter 格式是固定的：tags: 后有一个尾随空格，标签和分类都用 - 列表项，date 用 YYYY-MM-DD。手写文章时照这个格式，否则标签页会出现重复条目。
  • 全量构建约 2.5 分钟（155 篇文章 + 12MB 搜索索引），发布命令会显示常驻通知，跑完才消失，耐心等。
  • 本地预览端口固定 4000。若被占用，停止本地预览 会自动回收占用该端口的进程。
